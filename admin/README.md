# 本机内容后台

在项目根目录双击 **启动网站后台.cmd**，会自动打开浏览器。也可以运行：

```sh
npm install
npm run admin
```

打开 http://127.0.0.1:4322 。保持终端运行，按 Ctrl+C 关闭后台和它启动的网站预览。端口占用时，可在 PowerShell 中用 `$env:ADMIN_PORT=4323; npm run admin` 更换端口。

## 日常使用

1. **个人资料**：修改名字、首页简介、详细介绍、邮箱、社交链接、简历、技能与经历。
2. **博客文章 / 项目作品 / 荣誉证书**：新建、编辑、搜索、删除。支持 Markdown 正文预览和图片上传。可按 `Ctrl+S` 保存。博客文件可放在分类子目录中，文件名决定网址且必须唯一；已保存的文件路径固定，需要改路径时可在文件管理器中移动。
3. **素材库**：上传博客配图、项目封面、证书图片、简历 PDF。文件自动追加随机后缀，避免覆盖已有素材。复制路径后填入对应字段；在正文编辑器上传图片会自动插入 Markdown。
4. **网站设置**：修改导航和 giscus 评论配置。
5. **预览网站**：自动启动 Astro 本地预览。前台只展示已保存的内容；Markdown 预览可查看未保存的正文，沙箱中禁用脚本。
6. **发布与同步**：查看全部待提交文件，填写提交说明，点击「一键发布到 GitHub」。确认清单后，后台依次构建、提交、推送 `origin/main`。构建失败会停止发布，日志保留在页面上。推送完成后请打开「部署记录」查看 GitHub Actions 的部署结果。

保存仅修改本机文件。新文章默认草稿，取消草稿后保存，前台才会展示。**草稿仍会提交到 GitHub 仓库，前台隐藏不代表源文件保密。**

### 导入电脑里的文章

在「博客文章」或文章编辑页点击 **导入电脑文章**，选择原来的 `.md` 文件即可。无需填写 `D:\笔记\…` 或手动复制正文。支持 UTF-8 编码的 Markdown / Obsidian 笔记，单篇不超过 2 MB。

后台会识别 YAML 属性中的标题、日期、标签和分类，保留其他属性及正文。没有属性区时，标题取一级标题或文件名，日期使用文件修改日期。网址按文件名自动生成，同名文章追加编号另存，原文件不会被移动或修改。导入的文章统一存为草稿，点击「导入并保存」后可继续编辑。

如果正文有本地图片，导入窗口会列出引用。可以多选配图，或选择包含附件的文件夹（自动查找子文件夹）。由于浏览器不能擅自读取 Markdown 旁边的文件，需明确选择一次配图或文件夹。只复制正文引用的 PNG、JPG、GIF、WebP、AVIF，自动改写为网站图片链接；支持普通 Markdown 图片、Obsidian `![[图片.png]]`、引用式图片和 HTML `img`。代码中的图片示例保持原样，远程图片链接保持原样。

图片找不到或同名有歧义时，会提示处理，不会覆盖或猜测。如果暂时没有配图，可以勾选「缺失图片稍后补充」先保存草稿。单张图片不超过 10 MB，本次文章及图片编码后的请求总大小不超过 15 MB，超限请压缩图片再试。检查完效果后，取消草稿并保存，再前往「发布与同步」推送到 GitHub。

首次推送需本机 Git 已配置提交者（`git config user.name`、`git config user.email`）并完成 GitHub 登录。可先在终端通过 Git Credential Manager 完成认证，后台复用本机 Git 凭据，不保存 GitHub Token。如果推送失败，处理网络或认证问题后直接重试；已创建的本地提交不会丢失。远端有新提交时，需要在终端先处理同步或冲突，后台不会强制推送。

如果出现 `.git/index.lock: Permission denied`，说明运行后台的进程没有 Git 写入权限。请关闭当前后台，从 Windows 文件资源管理器双击「启动网站后台.cmd」启动，再刷新页面重试。Codex 沙箱启动的进程会继承 Git 目录的写入限制。此错误不代表存在残留锁文件，无需删除 `.git/index.lock`，也不应修改整个 `.git` 的访问控制。

## 文件和备份

- `src/data/site.json`：站点资料、关于页面、导航与评论配置。`src/config.ts` 将其提供给前台。
- `src/content/blog/`、`projects/`、`awards/`：保持原来的 Markdown 文件结构。
- `public/blog-assets/`、`projects/`、`certs/`、`resumes/`：素材。
- `.admin-backups/`：每次覆盖或删除前保存原文件，按时间和目录存放，已加入 Git 忽略。恢复时从备份中复制对应文件到原路径。后台不会自动清理备份。

如果内容同时被 Obsidian、VS Code 或另一个后台窗口修改，后台会阻止旧版本覆盖新版本。先复制当前未保存内容，再刷新重新编辑。

后台服务只监听 `127.0.0.1`，并检查 Host、Origin 和写操作会话令牌。它在 `admin/` 中运行，不进入 Astro 的公开页面或 `dist/`，无需服务器和在线登录系统。不要将本机后台转发到公网。

## 验证

```sh
npm run test:admin
npm run build
```

自动化测试使用临时目录与模拟命令，不会推送真实 GitHub 仓库。
